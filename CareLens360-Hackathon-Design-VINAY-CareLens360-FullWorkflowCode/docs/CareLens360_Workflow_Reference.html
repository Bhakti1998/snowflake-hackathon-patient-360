5. Document Processing Pipeline

Module: src/carelens/chunks.py (50 lines)

FunctionPurpose
split_page(text, count_tokens, max=800, overlap=75)Binary-search chunking: finds max word span within token limit, then walks backward for measured overlap. Returns chunks with text, token count, character offsets, and exception tags (SHORT_PAGE, RESIDUAL).

Module: snowflake/refresh.py (115 lines)

Snowpark stored procedure handler that runs inside Snowflake as REFRESH_WORKFLOW.

FunctionPurpose
run_wrapper(session, parse_limit)Procedure entry point; delegates to run()
run(session, database, parse_limit)Incremental pipeline: refreshes stage, finds unparsed docs, calls AI_PARSE_DOCUMENT with LAYOUT mode + page_split, measures tokens with COUNT_TOKENS, creates chunks, commits transactionally per document, audits to PIPELINE_AUDIT

Pending selection: a manifest document (ID + SHA256) is pending unless it has an error-free row in RAW.DOCUMENT_PARSE_RESULTS and chunks in CURATED.DOCUMENT_CHUNKS for the same SHA (CTE + LEFT JOIN, ordered by ID, bounded by parse_limit). Successful parses store ERROR as SQL NULL (bound via NULLIF(?, ''), since Snowpark binds Python None as the string 'None'). Entity reloads are not done inside the procedure (temp tables are unsupported there); the base phase loads structured data.

Processing Flow

1. PDF uploaded to @RAW.DATA_STAGE
2. Registered in RAW.DOCUMENT_MANIFEST (ID, SHA256, metadata)
3. AI_PARSE_DOCUMENT(TO_FILE('@DATA_STAGE', path), {mode:'LAYOUT', page_split:TRUE}, TRUE)
4. Parse result stored in RAW.DOCUMENT_PARSE_RESULTS
5. Each page split into chunks (500-900 tokens, 50-100 overlap)
6. Token counting via SNOWFLAKE.CORTEX.COUNT_TOKENS('snowflake-arctic-embed-m-v1.5')
7. Chunks inserted into CURATED.DOCUMENT_CHUNKS (transactional per document)
8. CHANGE_TRACKING on DOCUMENT_CHUNKS feeds Cortex Search incremental refresh

Chunk Metadata Preserved

CHUNK_ID, DOCUMENT_ID, MEMBER_ID, PATIENT_ID, PLAN_ID, DOCUMENT_TYPE, DOCUMENT_DATE, SOURCE_SYSTEM, AUTHOR_ROLE, CONDITION_GROUP, MEDICATION_NAME, PAGE_NUMBER, SECTION, SOURCE_FILE, CHUNK_TEXT, START_OFFSET, END_OFFSET, TOKEN_COUNT, OVERLAP_TOKENS, CHUNK_EXCEPTION, TOKENIZER, SHA256, CLASSIFICATION

6. Cortex Search Configuration

Six search services created in SEMANTIC schema, all with 1-hour target lag and incremental refresh:

ServiceScopeSource Filter
SHARED_EVIDENCE_SEARCHSafety/regulatory docs (no member)PLAN_ID='SHARED'
CARE_DOCUMENT_SEARCHAll member-specific docsPLAN_ID!='SHARED'
CARE_DOCUMENT_SEARCH_PLAN_1Plan 1 members onlyPLAN_ID='PLAN-1'
CARE_DOCUMENT_SEARCH_PLAN_2Plan 2 members onlyPLAN_ID='PLAN-2'
CARE_DOCUMENT_SEARCH_PLAN_3Plan 3 members onlyPLAN_ID='PLAN-3'
CARE_DOCUMENT_SEARCH_PLAN_4Plan 4 members onlyPLAN_ID='PLAN-4'

Searchable: CHUNK_TEXT
Filterable Attributes: MEMBER_ID, PATIENT_ID, DOCUMENT_TYPE, DOCUMENT_DATE, SOURCE_SYSTEM, AUTHOR_ROLE, CONDITION_GROUP, MEDICATION_NAME
Returned to the agent per result: doc_id (CHUNK_ID = DOCUMENT_ID:SHA256:PAGE:INDEX), doc_title (DOCUMENT_ID), text, a columns object with PAGE_NUMBER, SOURCE_FILE, DOCUMENT_DATE, DOCUMENT_TYPE and MEDICATION_NAME, plus stage_path/relative_path pointing at the source PDF on @RAW.DATA_STAGE. The extra columns appear only because the agent spec declares them (see section 8).

8. Cortex Agent

Module: src/carelens/agent.py (99 lines)

Generates YAML specification for CREATE AGENT. Five agents: 1 admin-only global + 4 plan-scoped. Orchestration budget is 300 seconds / 32,000 tokens (a member summary at 120s timed out live); the orchestration instructions ask for the member snapshot and risk factors in one PatientAnalytics call to keep tool calls low.

10. Streamlit Application

Module: app/streamlit_app.py (156 lines)

Four-screen evidence copilot deployed as a Snowflake-hosted Streamlit app. Calls /api/v2/databases/<DB>/schemas/APP/agents/<plan agent>:run via _snowflake.send_snow_api_request with "stream": false and a 360-second timeout; catches SnowparkClientException.

ScreenFeatures
Member SearchFilter by risk tier and condition key; member count metric; data table + risk tier bar chart
Member 360Demographics snapshot; 7 detail sections (diagnoses, medications, encounters, labs, claims, care gaps, risk factors); audit logged
Evidence CopilotNatural-language question box; plan-scoped Cortex Agent invocation; citation verification against source chunks; conflict/insufficient evidence warning banners; "Evidence/tool inputs" expandable panel; scope refusal detection; conversation history (last 10 messages)
Population InsightsHigh+Critical member count; risk tier distribution chart; risk-by-condition pivot table; utilization/adherence/care-gap metrics table; audit logged

Safety Guards

  • Pipeline status check — blocks if refresh is running/failed
  • Document readiness check — blocks if required documents pending/failed
  • Citation plan/member/chunk verification — withholds unverifiable answers
  • Context invalidation on data version change
  • Synthetic data disclaimer banner

11. Governance

Five Roles

RoleAccess Level
CARE_ADMINFull: all schemas, raw write, agents, search, semantic views, task control, entitlement management, Streamlit
CARE_DATA_ENGINEERPipeline: RAW/CURATED/SEMANTIC read+write, stages, procedure, file format
CARE_ANALYSTRead: APP governed views only
CARE_REVIEWERRead: APP governed views only
CARE_DEMO_USERStreamlit only (gated until isolation tests pass)

Data Controls

  • Row Access Policy: MEMBER_PLAN_POLICY filters by USER_ENTITLEMENTS (plan-based or * wildcard)
  • Classification: CLASSIFICATION='SYNTHETIC' column on DIM_MEMBER, RISK_FACTORS, DOCUMENT_CHUNKS, USER_ENTITLEMENTS
  • Access Audit: Every Streamlit operation logged to APP.ACCESS_AUDIT (request_id, user, plan, operation, status)
  • Pipeline Audit: Every parse/refresh run logged to RAW.PIPELINE_AUDIT (run_id, operation, status, details, timestamps)
